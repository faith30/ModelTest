# 准备记录与扣分边界

本仓库根据用户的明确选择采用“独立抽象仓库 + 静态细节审查”，不是 UE 功能回归或移植完成声明。制作、配置、控制逻辑的缺项被移除到候选模板中；现有 UE 项目、既有 AnimationMarkBench 和 AnimationLoopBench 不变。

## 本地证据优先级

1. `source-audit.json`：当前源文件哈希与已有只读导出核对。确认材料仍对应当前文件。
2. `local_lyra_facts.json`：有界序列化属性和函数字节码证据。不能当完整可执行图。
3. `rubric.json` 的官方来源：界定机制和关注点。网页版本号不替代本地版本，具体数字阈值和未导出默认值不能凭网页推定。
4. 任务设计约定：输入坐标、抽象接口、可重复生成与输出格式。按本题公开契约判断，不冒充 Epic 原始实现。

先前资料中的 `candidate_context.json` 原本是打点题给模型的上下文；本题会考察同步组与图制作，因此同一资料转为裁判专用。不能因为文件曾名为 candidate 就把完成答案发给本轮考生。

## 删除/保留表

| 内容 | 候选包 | 原工程 |
|---|---|---|
| 原始姿态抽样、骨架顺序、目录元数据 | 保留，去除导出来源路径与加工答案 | 不修改 |
| 制作器算法、完成的 marker/curve/notify | 移除，只保留空接口 | 不修改 |
| 动画图状态条件、同步组角色、资源绑定答案 | 移除，只保留空配置 | 不修改 |
| 控制器逻辑 | 移除，只保留方法签名 | 不修改 |
| Lyra 蓝图导出、裁判清单和历史答案 | 不打包 | 不修改 |
| 通用格式/输入输出契约 | 保留 | 不修改 |

模板内的 TODO 和空表本身不代表基线已经完成。裁判资料是“关键事实与验收依据”，本版没有制作一个冒充唯一正确答案的模拟器。

## 不同能力分别报告

- 资源加工、状态与方向、同步、距离匹配、姿态修正、层与生命周期、稳定性分别给分。
- 模型交付失败与内容缺陷分别记录；工具故障、无法访问素材、审查未完成不记成模型遗漏。
- 引用成立只证明文件确有这些文字。评测者仍须确认定义、调用、数据引用和分支处理一致。
- 不要求每个 Lyra 名称照抄；不把原作者绝对打点时间当自然唯一真值。
- 元数据资产没有采样，不能按“没有正确时间点”扣分。通用制作算法、缺输入分支和资源引用仍可审查。
- 姿态修正只审查抽象计算/计划和消费关系，不能将通过称为滑步少、观感好或完整骨骼正确。

## 正式比较前冻结

同一输入ZIP、题目、工具、时间预算、允许联网范围、请求强度和裁判清单；记录实际响应模型与请求模型，是否真实执行某强度如果不可见则如实标注。代码和答案交付后不再由评测端改写。失败重试另记一次，不选最好的一次覆盖原记录。

静态结论更适合解释“模型遗漏了哪些动画工程细节”，不能据此单独建立所有游戏动画制作能力的排名。正式模型运行尚未启动。
