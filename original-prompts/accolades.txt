# 连杀荣誉系统开发任务

在现有 Lyra 射击体验中实现完整的连杀荣誉系统。玩家达成短时间连续击杀或存活期间累计击杀时，系统应在该玩家 HUD 显示对应荣誉、图标和声音。交付物必须覆盖 C++、蓝图、数据配置、Widget 和体验接入，能通过真实射击对局触发；只实现算法、只写说明或直接在测试入口弹出提示均不算完成。

## 起始条件与范围

工程已提供角色、伤害与击杀事件、Gameplay Message、Experience/Game Feature、HUD 扩展、Data Registry 和素材等公共能力。荣誉的原有业务实现及专属配置已剥离，部分资源保留为空壳，以维持公共资源引用及反射类型稳定。首先检查当前工程状态，再完成设计和实现。

保持 `UElimChainProcessor`、`UElimStreakProcessor`、`ULyraAccoladeHostWidget`、`FLyraAccoladeDefinitionRow` 及现有蓝图路径可用。可扩展这些类型、增加本功能专属文件或资源，但不得通过关闭已有游戏体验、删除公共接入或改变公共击杀事件含义来绕过任务。

`AssistProcessor`、`B_EliminationFeedRelay`、比分/计分板、伤害与死亡流程属于公共系统，必须保留原有行为。本题不要求开发新的助攻规则。现有图标、材质和音频可以复用，视觉不要求逐像素复刻。

## 玩家可见行为

1. 同一玩家相邻两次有效击杀间隔不超过 **4.5 秒**时计入同一组连续击杀；超过该间隔后重新计数。达到 **2、3、4** 次时分别触发双杀、三杀、四杀。4.5 秒边界包含在有效区间内。
2. 同一玩家在两次死亡之间累计有效击杀数，在 **5、10、15、20** 次时分别触发对应存活连杀荣誉。玩家死亡后下一次有效击杀重新计数。各玩家独立，不串号。
3. 自杀不增加任何击杀荣誉计数；它仍属于该玩家死亡，必须重置其存活连杀记录。无有效攻击者的死亡不奖励攻击者，但同样重置死者的存活连杀记录。
4. 每个阈值仅在达到时触发一次，未配置的阈值不产生替代或重复通知。两个荣誉类别独立工作；一次击杀可以同时达成两类荣誉。
5. 荣誉只出现在获奖玩家的 HUD。服务器负责奖励判定；其他玩家、其他本地玩家视图和专用服务器不播放该荣誉的 UI/声音。Listen Server 的本地玩家和远端客户端都应正常收到各自荣誉。
6. 提示包含名称、图标、音效和显示时长。显示位置与持续时间由资源配置。相同类别的更高等级荣誉能取代正在显示或排队的低等级荣誉；不同类别的提示按触发顺序展示，不相互吞掉。
7. 同一时刻一个荣誉位置只显示一条提示。资源异步加载完成顺序不能改变触发顺序；失效行、缺失可选图标/音效或无效显示时长不能使后续提示永久停止。图标或音效缺失时至少保留文字反馈，并给出可定位的低频诊断。
8. 重生、HUD 重建、关卡切换和体验卸载后不残留旧提示、定时回调或重复监听。玩家离开后，其历史记录不应长期阻止对象释放。

## 验收场景

| 场景 | 预期结果 |
| --- | --- |
| 玩家 A 在 0、4、8、12 秒各击杀一次 | 产生双杀、三杀、四杀；不是按首次击杀到最后击杀的总时长判断 |
| 相邻击杀间隔为 4.5 秒、以及大于 4.5 秒 | 前者继续连续击杀，后者重新开始 |
| A 达到 5/10/15/20 次有效击杀，期间不死亡 | 对应存活连杀荣誉每档一次 |
| A 击杀 4 次后死亡，再击杀 1 次 | 不触发 5 次存活连杀荣誉 |
| A 自杀、无攻击者死亡、A 与 B 交错击杀 | 不错误奖励，不串玩家记录，死者存活连杀被重置 |
| 同时满足连续击杀与存活连杀阈值 | 两类荣誉均可见，顺序稳定 |
| 双杀尚未显示完时达成三杀 | 三杀替换低等级连续击杀提示，旧提示不在队尾再次出现 |
| 两客户端连接专用服务器；另测 Listen Server | 只有获奖者收到提示，服务器无 UI/音效，客户端之间不泄露提示 |
| 模拟慢资源加载、无效行和缺失可选素材 | 不乱序、不崩溃、不永久堵塞；后续有效提示继续出现 |
| HUD 反复构建/销毁、重生、退出再进入体验 | 无重复奖励、旧提示或失效对象回调 |
| 普通对局及助攻/击杀播报回归 | 比分、计分板、公共击杀播报和游戏流程保持可用 |

可增加自动化或开发期事件驱动入口以稳定复现时间与阈值，但必须另有从真实伤害/击杀到最终 HUD 的端到端证据。测试入口不能成为正式触发链路。
