# 无历史评测副本

三个测试分支仍继承项目的完整 Git 历史，单独切换分支不能隔离参考答案。正式评测应从准备完成并提交的测试分支导出无历史副本，并在隔离的评测环境中限制模型访问原仓库、其他工作树和参考实现。仅创建一个新目录不能形成访问隔离。

本目录的 `export_snapshot.py` 仅依赖 Python 3.9+ 标准库，以及系统中的 Git 和 Git LFS。脚本从自己的位置确定项目根目录，不依赖运行命令时的当前目录。

```powershell
python .\Benchmarks\tools\export_snapshot.py --destination D:\ModelEvaluations\interaction-model-a
```

准备条件：先提交测试分支全部已跟踪改动，并确保 LFS 资产已落地为真实文件。目标目录必须尚不存在，且位于源目录以外，也不能是源目录的祖先。路径会解析后再检查；脚本拒绝符号链接资产、子模块、未落地 LFS 指针及需要另外审查的 `.lfsconfig`/`.gitmodules` 传输配置。

脚本通过 `git ls-files -z` 获取清单，复制当前工作树中的已跟踪文件。忽略文件和未跟踪文件允许留在源目录，但不进入副本；`.git`、原提交历史和原仓库 remote 不会复制。新仓库独立安装本地 LFS 支持，重新写入自己的 LFS 对象，创建 `main` 分支和唯一的根提交 `Benchmark starting snapshot`。提交使用固定的 Benchmark Snapshot 身份，不继承源仓库作者信息。为保留原本已跟踪但匹配 `.gitignore` 的文件，暂存时使用 `git add -A --force`。

新仓库创建期间不读取全局或系统 Git 配置，避免继承外部 hook、签名、remote 或共享 LFS 存储设置。完成后核验单根提交、无 remote、文件清单一致和工作树干净。脚本不会推送、联网下载或删除任何目录；失败时保留已创建目录并报错，排查后应选择新的目标目录重试。

导出的内容以已提交的 tracked 文件为准，包括本分支选择跟踪的题目和说明。准备者需要自行确认其中没有评测时不该公开的参考材料。模型运行环境仍需由评测者隔离；该脚本只负责创建独立的起始仓库。
